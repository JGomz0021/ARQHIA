# v0.9.4 — Hardening crítico (seguridad + datos + compat)

> Nace de la auditoría integral 2026-09-14 (TOP 1–5). Sin esta versión no hay
> puerta v0.9.6: corrige lo que puede perder datos o ejecutar código fuera del
> workspace. Sin cambios de comportamiento salvo mayor seguridad.

## Objetivo
Cerrar los huecos críticos de seguridad, persistencia y compatibilidad antes
de refactorizar: escape por symlinks + `build.rs`, DB sin constraints,
tests contra la DB real del usuario, `HOME` manual (rompe Windows) y
`config.toml` sin `600`.

## Alcance (concreto)

### A. Workspace anti-escape (`agent/tools.rs::resolve`)
1. Tras `resolve()`: `canonicalize` del destino si existe; si es symlink que
   apunta fuera de `ws_canon` (o de `extra_paths` canonicalizados) → denegar
   con `⛔ Fuera del workspace (symlink)`.
2. `write_file/edit_file/delete_file/read_file/list_dir` heredan el guard sin
   rama nueva (solo endurecen `resolve`).
3. Import con `cargo` (`questionnaire/import.rs::scan_import` + banner):
   aviso explícito "este proyecto puede ejecutar `build.rs` al hacer
   `cargo build/test`; revisa antes de Work con `auto_bash`".
4. Auditoría `bash`: confirmar si el executor usa `sh -c` (`tools.rs:517-560`);
   si sí, pasar a `exec` directo sin shell + allowlist exacta por argv[0].
   `cargo test; curl…` no debe colarse por concatenación.

### B. Persistencia (`db.rs::init/migrate_stack`)
1. `PRAGMA foreign_keys=ON` + `FOREIGN KEY (chat_id) REFERENCES chats(id)
   ON DELETE CASCADE` / `chats.project_id → projects(id) ON DELETE SET NULL`
   para DBs nuevas; en DBs viejas, limpieza de huérfanos + índice.
2. Índices: `idx_messages_chat (messages.chat_id)`,
   `idx_chats_project (chats.project_id)`.
3. `projects.name UNIQUE COLLATE NOCASE` (la unicidad deja de vivir solo en
   `project_name_exists`); `free_project_name` sigue como UX.
4. `schema_version INTEGER` en tabla `meta` (1 fila, `version=1`); `init()`
   la crea y la sube por migración. Base del backup pre-migración v0.9.5.
5. `stack_fts` en transacción con `stack_items` (`stack::save`): insert + FTS
   en una `IMMEDIATE`, como `copy_chat/branch_chat`.
6. `delete_project` aclara contrato: borra chats del proyecto (CASCADE) o los
   suelta (SET NULL) — una sola semántica + test. Sin ambigüedad UI/DB.

### C. Tests fuera de la DB del usuario
1. `db.rs::tests` + `stack/tests` + `usage` pasan a `tempdir` (env
   `ARQHIA_TEST_DIR` o `Connection::open_in_memory` con `migrate_stack`);
   prohibido `db_path()` real en `#[cfg(test)]` (test que lo detecte).
2. `copy_and_branch`, `usage_counts`, `session_id` re-verdes en temp.

### D. Compat + secretos
1. `HOME` manual → `directories::ProjectDirs` (`config.rs::config_path`,
   `db.rs::db_path`, `pricing.rs::cache_path`, `skills.rs`, papelera).
   Nuevo crate: solo `directories`. Fallback a `HOME` si no hay dirs.
2. `config.rs::save()` + `license.rs` futuro + `cloud_token` v1.0: `chmod 600`
   en Unix (`std::os::unix::fs::PermissionsExt`). Test que lo verifica.
3. `fetch_url`: bloque `localhost/127.0.0.1/169.254.169.254` + redirect máx 3
   (tope 64k ya existe). Test SSRF local.

## Criterio Done (estricto)
* `symlink → /etc/passwd` dentro del ws → denegado; symlink interno OK.
* `cargo test; curl evil` → denegado por allowlist exacta.
* `PRAGMA foreign_key_list` no vacío en DB nueva; `EXPLAIN QUERY PLAN`
  usa índices por `chat_id/project_id`.
* `cargo test` no crea ni toca `~/.local/share/arqhia/arqhia.db`
  (verificado con `strace`-mental: test de guarda).
* `config.toml` con `600` en Unix; Windows no escribe en CWD.
* `fetch_url http://127.0.0.1/` → error claro, sin petición.

## Test de Funcionalidad
1. Crear symlink externo en ws → `read_file` lo deniega; archivo normal OK.
2. Abrir carpeta con `build.rs` malicioso → banner visible; Work pide
   `auto_bash` antes de compilar.
3. `delete_project` → 0 chats huérfanos (`COUNT WHERE project_id NOT IN`).
4. `cargo test` dos veces seguidas → verde, DB del dev intacta.

## Riesgos
* `UNIQUE name NOCASE` rompe DBs con duplicados previos → migración los
  renombra (`free_project_name`) antes del índice, con aviso en Log.
* `directories` cambia rutas en Windows → documentar en `PROJECT.md §12`
  + no mover datos viejos sin preguntar.
