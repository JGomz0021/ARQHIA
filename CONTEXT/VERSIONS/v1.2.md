# v1.2 — macOS: firma Developer ID + notarización

## Objetivo
Abrir macOS como plataforma vendible **solo cuando haya base de usuarios**.
Cerrar las tres plataformas de escritorio (Linux + Windows ya en v1.0/v1.1) con
un instalador firmado y notarizado que abra sin bypass de Gatekeeper.

## Condición de entrada (gate obligatorio)
No se empieza v1.2 hasta cumplir **ambos**:

*   **50–100 usuarios PRO de pago** (umbral a fijar al cierre de v1.1 con datos
    reales de retención).
*   Insumos listos: cuenta Apple Developer activa y binarios de v1.1 estables.

Si no se cumple, la versión queda en `☐ Pendiente` y no se consume esfuerzo.

## Alcance (concreto)

### A. Firma y notarización
*   Apple Developer Program (**$99/año**) → certificado **Developer ID
    Application**.
*   `codesign` del binario y del `.dmg`/`.tar.gz`; **notarización** con
    `notarytool` (obligatoria desde Catalina) + `stapler`.
*   Sin firma/notarización Gatekeeper bloquea; **no se acepta** como Done.

### B. Empaquetado
*   Target **`aarch64-apple-darwin`** primero (Apple Silicon, mayoría de
    indies); `x86_64` (o universal) solo si el CI lo da gratis.
*   Formato `.dmg` (o `.tar.gz` firmable como mínimo viable) generado en CI
    macOS (`cargo build --release`).
*   Mismo checklist que `.deb` (v0.9) y MSIX (v1.0): abre, conserva
    `arqhia.db`/`config.toml`/workspaces, funciona offline contra STACK local,
    y Trial/Pro se validan igual (misma pubkey).

### C. Rutas y sistema
*   Rutas mac: config `~/Library/Application Support/arqhia/` con fallback a
    `~/.config/arqhia/` si no existe (no duplicar datos); DB igual. Documentar
    la ruta efectiva en CHANGELOG y `Config → Cuenta`.
*   `xdg-open` (links de markdown) → usar `open` en mac.
*   `rfd::pick_files/pick_folder` e Iced funcionan sin cambios mayores.
*   Updater: mismo manifiesto `latest.json`; en mac añadir bloque `macos` con
    URL + sha256 (ver `CONTEXT/WEB.md` §4).

## Paso a paso
1.  Alta Apple Developer + certificado Developer ID.
2.  Job CI `macos-latest` (`cargo build --release --target aarch64-apple-darwin`).
3.  `codesign` + `notarytool submit --wait` + `stapler staple`.
4.  `create-dmg` o script; publicar en la web (`/download`).
5.  Adaptar `open` vs `xdg-open` + rutas mac + fallback config.
6.  QA en Mac limpio (Apple Silicon) + docs + release notes.

## Tareas técnicas
*   Modifica: `views/chat.rs` y util de apertura de enlaces (`open`/`xdg-open`),
    resolución de rutas de config/DB en `config.rs`/`db.rs`.
*   Packaging: job CI macOS + script `create-dmg`; sin nuevas dependencias Rust.
*   Extiende `updates.latest.json` con bloque `macos`.

## Criterio Done (estricto)
*   Gate cumplido (50–100 PRO de pago) y documentado al abrir la versión.
*   `.dmg` instalado en Mac limpio (Apple Silicon): **abre sin bypass** de
    Gatekeeper (firmado + notarizado).
*   Conserva `arqhia.db`/`config.toml`/workspaces previos.
*   Offline contra STACK local funciona; Trial/Pro se activan igual que en
    Linux/Windows.
*   `cargo test` + `cargo clippy --all-targets` verdes.

## Test de Funcionalidad
1.  Instalar `.dmg` en mac limpio → abre (sin "clic derecho → Abrir").
2.  Chat + agente + STACK local OK sin red.
3.  Activar Trial con la misma pubkey que Linux/Windows.
4.  Updater detecta una versión superior y muestra el banner.

## Riesgos
*   Notarización rechaza binarios con entitlements raros → revisar logs de
    `notarytool`; `rfd`/badging pueden requerir ajustes.
*   CI macOS coste/tiempo → cachear y construir solo en tags de release.
*   Apple cambia requisitos de notarización → fijar documentación de la versión.
*   Sin base de usuarios, abrir mac puede no compensar → el gate lo evita.

## Dependencias
v1.1 completa (licencias + Pro). Requiere `WEB` para publicar descargas y
manifiesto mac. No se puede saltar v1.1.
