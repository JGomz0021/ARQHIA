# v0.9.2 — Skills de dominio (UI/UX, CodeReview, Test/QA → CONTEXT/)

## Objetivo
Sobre la infra `/skill` de v0.9 Track C, añadir 3 skills de dominio embebidas cuyos **resultados se guardan en `CONTEXT/`** para que el Orquestador los lea en el siguiente turno.

## Alcance (concreto)
* **Formato**: igual que Track C (`SKILL.md` frontmatter + cuerpo ≤8KB, `include_str!`, instaladas a `~/.local/share/arqhia/skills/` al arrancar si faltan). Sin permisos propios: sus scripts pasan por el permiso Bash existente.
* **Skills nuevas**:
  1. `ui-ux`: checklist visual (jerarquía, contraste, espaciados `design::gap/pad`, densidades, responsive, estados vacíos/errores) → escribe `CONTEXT/UI-REVIEW.md` (hallazgos + propuestas por pantalla).
  2. `code-review`: seguridad (inyección, escapes de workspace **incl. symlinks v0.9.4**, secretos en logs, `unwrap` en producción, `build.rs` al importar, `ChatHistory` desalineado v0.9.5), errores, alternativas, deuda → `CONTEXT/CODE-REVIEW.md` (severidad Alta/Media/Baja por archivo:línea).
  3. `test-qa`: ejecuta `check/test/clippy`, lee el Log, propone y (con permiso) ejecuta pruebas personalizadas → `CONTEXT/QA-REPORT.md` (tabla pass/fail + comandos).
* **Invocación manual + sugerida**: `/skill ui-ux|code-review|test-qa [texto]` inyecta la skill una vez y el turno sigue (Chat/Plan/Work según modo); skill inexistente → error con lista. Además el Auditor, al cerrar con ISSUES, **sugiere** en el Log `Prueba /skill code-review` o `/skill test-qa` (no auto-ejecuta).
* **Persistencia legible**: `agent::read_context_docs` suma `UI-REVIEW.md, CODE-REVIEW.md, QA-REPORT.md` (+ tope 1500 c/u) y `CONTEXT.md` los indexa. Offline intacto.

## Criterio Done (estricto)
* `/skill ui-ux "revisa el chat"` → `CONTEXT/UI-REVIEW.md` creado y citado en la respuesta.
* `/skill code-review` en repo con `unwrap` productivo → lo señala con archivo:línea.

## Test de Funcionalidad
1. `/skill ui-ux` sobre el chat → propone 3 mejoras de espaciado/densidad.
2. `/skill code-review` → 0 Altas en código limpio; con `unwrap` inyectado → 1 Alta.
3. `/skill test-qa` tras romper un test → QA-REPORT FAIL + sugerencia de fix.
4. Auditor con ISSUES → Log sugiere la skill adecuada sin ejecutarla.

* Skill que pide ejecutar scripts → pasa por aprobación Bash si `auto_bash=false`.
