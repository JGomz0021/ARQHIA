# v0.9 — STACK local de código (etiquetas + búsqueda + metadatos)

## Objetivo
Crear el STACK de código local con funciones completas: etiquetas, búsqueda con ranking y metadatos.

## Alcance (concreto)
*   Esquema SQLite (en `arqhia.db`):
    ```sql
    CREATE TABLE stack_items(id INTEGER PK, title TEXT NOT NULL, code TEXT NOT NULL, tags TEXT NOT NULL /*csv*/, lang TEXT, rating REAL DEFAULT 0, executions INTEGER DEFAULT 0, created_at TEXT);
    CREATE TABLE stack_meta(item_id INTEGER FK, key TEXT, value TEXT); -- deps, versiones, bugs, opiniones_usuario, opiniones_ia
    CREATE VIRTUAL TABLE stack_fts USING fts5(title, code, tags);
    ```
*   Funciones en `src/stack.rs`:
    1.  `save(title, code, tags: Vec<String>, lang, meta: HashMap) -> id` (inserta + sincroniza FTS).
    2.  `search(query: String, filter_tags: Vec<String>) -> Vec<ScoredItem { id, title, snippet_preview 200 chars, score }>` con `score = tag_match*2.0 + fts_rank + rating*0.5`, orden desc, límite 20.
    3.  `get(id) -> FullItem { code completo, meta }`.
    4.  `rate(id, stars 1-5, opinion: String, by: User|IA)` actualiza `rating = avg` + inserta en `stack_meta`.
    5.  `record_execution(id, ok: bool)` y `report_bug(id, desc)`.
*   UI panel STACK (accesible desde Chat con `button("STACK")` → `View::Stack` o panel lateral derecho 300px):
    *   `text_input(buscar) + row[text_input(tags csv) + button(Buscar)] + scrollable(resultados: button(título + tags + ★rating)) + preview(code 15 líneas + metadatos deps/versiones/bugs) + row[button(Copiar a workspace), button(★ Valorar)]`.
    *   `button(+ Guardar selección)` guarda snippet desde portapapeles o desde archivo del workspace (`pick archivo + text_input(tags)`).
*   Integración agente: `agent` puede llamar `stack_search` antes de generar código (en v0.9 manual vía Log, auto total en v1.0). Seed inicial 10 snippets (ej. `rust-hello, axum-health, sqlite-open, iced-counter...`).
*   `stack_path` de Config v0.7 apunta a la DB (default `~/.local/share/arqhia/arqhia.db`).

## Paso a paso
1.  Habilitar `rusqlite` con `bundled` + FTS5, crear migración `migrate_stack()` en `db.rs`.
2.  Implementar `src/stack.rs` con las 5 funciones + tests `save→search→get→rate`.
3.  Crear `src/views/stack.rs`: buscador + lista + preview + guardar/valorar, `Message::{StackSearch, StackSelect(id), StackSave, StackRate}`.
4.  Seed `src/stack/seed.rs` con 10 snippets y `fn seed_if_empty()`.
5.  Conectar con orquestador v0.6: `plan()` hace `stack::search(keywords)` y lo inyecta al prompt worker (log "STACK: 2 hits").
6.  Verificar persistencia tras reinicio y `cargo test stack`.

## Tareas técnicas
*   Archivos: `src/stack.rs` (+`seed.rs`), `src/views/stack.rs`, modifica `db.rs, orchestrator.rs`.
*   Scoring exacto documentado arriba, no genérico.

## Criterio Done (estricto)
*   Guardar snippet con tags + meta persiste y aparece en FTS.
*   Buscar "auth" con 5 seeds retorna top 2 correctos con rating visible.
*   `get` retorna código copiable a `workspace/Proyecto/` manualmente y compila.
*   `rate` y `report_bug` actualizan metadatos visibles en preview.
*   Reinicio conserva todo.

## Test de Funcionalidad
1. Guardar 5 snippets (auth, db, api, ui, test), buscar "auth" → top 2 con ★.
2. Valorar 5★ + opinión, verificar rating cambia.
3. Desde agente pedir "usa STACK para health endpoint", verificar Log muestra hits.

## Riesgos
*   FTS5 no disponible → compilar `rusqlite` con `bundled-full` y test en CI Linux.

## Dependencias
v0.8 (cuestionario genérico + niveles + IA, `PROJECT.md`/`SPECS.md`) + v0.6 (orquestador).

# v0.9 Track B — Identidad, consentimiento, legalidad, uso e instalador Linux

## Objetivo B
STACK legalmente sano desde el día 1, identidad local para firmar metadatos,
visibilidad de consumo e instalador Linux con CI mínimo.

## Alcance B (concreto)
*   **Esquema legal** (desde el inicio, no como parche):
    `stack_items(... author TEXT NOT NULL, license TEXT NOT NULL DEFAULT 'Uso interno',
    source TEXT NOT NULL DEFAULT 'local')`.
    Licencias admitidas al compartir: `MIT`, `Apache-2.0`, `Uso interno`
    (esta última nunca sube a la nube; el push la rechaza con error claro).
*   **Consentimiento** (Config→STACK o Cuenta; todo default OFF):
    `use_stack` (usar STACK en mis tareas), `share_local` (guardar lo mío en
    local), `share_cloud` (subir a nube; exige sesión v1.0, si no existe avisa).
    Sin consentimiento no hay subida. Ver `CONTEXT/POLICIES.md` §4.
*   **Identidad local** (Config→Cuenta): `name + email`, solo para firmar
    `author` de metadatos. Sin contraseñas, sin servidor. Validación mínima
    (nombre no vacío, email con `@`).
*   **Contador de uso local**: turnos, tool calls por categoría y errores 429
    por proyecto (tabla `usage`; solo conteos, sin contenido). Panel mínimo en
    el sidebar o Config con totales. Sin esto, los límites v0.7 son ciegos.
*   **Respeto a consentimiento en el agente**: si `use_stack=false`, `plan()`
    no consulta el STACK (ni Log de hits); si `share_local=false`, el agente
    nunca propone guardar snippets.
*   **Instalador Linux + CI mínimo**: `.deb` (cargo-deb o script) + tarball
    `.tar.gz`; pipeline mínimo (check + test + clippy + build) que debe pasar
    antes de empaquetar. Sin CI, el instalador se pudre: el CI es prerrequisito,
    no opcional.
*   Migración de datos documentada: el instalador jamás borra `arqhia.db`,
    `config.toml` ni workspaces (ver `POLICIES.md` §7).

## Criterio Done B
*   Push con licencia `Uso interno` → rechazado con mensaje (nada sube).
*   Los 3 switches OFF por defecto en instalación limpia; activarlos persiste.
*   `share_local=false` + pedir "guarda esto" → el agente no lo propone/guarda.
*   Panel de uso muestra turnos y 429s del proyecto.
*   `.deb` instala en sistema limpio, abre, conserva DB/config previas; CI verde.

## Test de Funcionalidad B
1. Crear snippet con licencia MIT + consent ON → aparece con autor visible.
2. Intentar compartir con `Uso interno` → error claro, nada en la nube/mock.
3. Todo OFF → pedir al agente que use/guarde STACK → se niega y explica cómo activarlo.
4. Instalar .deb en contenedor limpio → abre y funciona.

## Riesgos B
*   Licencias mal marcadas por el usuario → el autor declara, ARQHIA no audita
    (aviso visible al compartir).
*   Alcance: no implementar auth real aquí (eso es v1.0).

## Dependencias B
v0.7 Track B (permisos/límites) + v0.7.1 (agente eficiente) + v0.8. La nube real sigue siendo v1.0.

# v0.9 Track C — Skills locales (`/skill` + pestaña Config)

## Objetivo C
Skills instalables en local invocables con `/skill nombre` en el chat, más
pestaña de administración en Configuración. Formato: carpeta por skill con
`SKILL.md` + recursos/scripts. Las descargables del STACK llegan en v1.0 §G.

## Alcance C (concreto)
*   **Formato en disco** (`~/.local/share/arqhia/skills/{nombre}/`):
    *   `SKILL.md` con frontmatter (`nombre, descripcion, version, autor,
        licencia`) + instrucciones markdown (tope 8 KB; más allá se trunca
        con aviso en el Log).
    *   `scripts/` y `recursos/` opcionales (plantillas, ejemplos).
*   **`src/skills.rs`** (nuevo):
    1.  `skills_dir()` → `~/.local/share/arqhia/skills/` (la crea si falta).
    2.  `list()` → embebidas + disco (nombre, versión, descripción, origen).
    3.  `load(nombre)` → frontmatter + cuerpo validados (falla claro si falta
        `nombre`/`descripcion`).
    4.  `parse_skill_message(input)` → `Some((nombre, resto))` si el input
        empieza por `/skill ` (con/sin resto), `None` si no.
*   **Skills embebidas** (vienen con ARQHIA, `include_str!`, se instalan a
    disco en el primer arranque si faltan): `commit-msg`, `revisar-codigo`.
*   **Invocación `/skill nombre [texto]`** (handler de chat, antes del
    dispatch por modo): resuelve embebida → disco; inyecta `SKILL.md` (+
    índice de `scripts/`/`recursos/`) UNA vez como mensaje de contexto y el
    turno continúa normal (Chat/Plan/Work según modo). Skill inexistente →
    error amable con la lista de instaladas.
*   **Pestaña Config → `Skills`** (7ª): lista con badge de origen
    (`embebida`/`local`), botón `Recargar`, borrado solo de locales (las
    embebidas se restauran desde el binario), aviso de que los scripts usan
    el permiso Bash existente.
*   **Permisos**: la skill NO trae permisos propios. Leerla es lectura;
    ejecutar sus scripts pasa por la política Bash ya existente
    (`POLICIES.md` §1). Sin excepciones.

## Paso a paso C
1.  `src/skills.rs` (`skills_dir/list/load/parse_skill_message`) + tests
    (frontmatter válido/inválido, parseo con/sin resto, truncado 8 KB).
2.  Embebidas `commit-msg` + `revisar-codigo` (`src/skills/embebidas/`) +
    instalación a disco si faltan + test.
3.  Parseo `/skill` en `handlers/chat.rs` (antes de `start_turn`) +
    inyección como contexto + test (inyecta una vez, inexistente lista).
4.  `ConfigTab::Skills` + card en `config_view.rs` (lista/origen/recargar/
    borrar/restaurar) + dispatch en `main.rs` + test de vista sin panic.
5.  `cargo test skills` + `cargo clippy`.

## Tareas técnicas C
*   Archivos: `src/skills.rs` (nuevo), `src/skills/embebidas/*.md`,
    modifica `app/events.rs`, `app/handlers/{chat,config}.rs`,
    `views/config_view.rs`, `main.rs`, `app/state.rs` (staging de pestaña).
*   Sin crates nuevos. Sin cambios a STACK ni a la política de permisos.

## Criterio Done C (estricto)
*   `/skill commit-msg <texto>` inyecta la skill y la respuesta la sigue.
*   `/skill inexistente` → error con la lista de instaladas, sin turno.
*   Pestaña Skills lista 2 embebidas; borrar una local + `Recargar`;
    borrar embebida → se restaura.
*   Un script de skill pedido por el agente pasa por aprobación Bash si
    `auto_bash=false`.

## Test de Funcionalidad C
1.  `/skill commit-msg "añade login"` → respuesta con formato de commit.
2.  `/skill noexiste` → error + lista.
3.  En Config → Skills: borrar `commit-msg` (restaura), crear carpeta local
    `mi-skill/` con `SKILL.md` válido → `Recargar` la lista, borrar la
    elimina.
4.  Con `auto_bash=false`, pedir ejecutar un script de la skill → modal de
    permiso.

## Riesgos C
*   `SKILL.md` gigante → tope 8 KB con aviso (no se envía entero al LLM).
*   Nombre con `../` o raro → slug validado, fuera de `skills/` se rechaza.

## Dependencias C
v0.8 (chat + wizard) + v0.7 Track B (permiso Bash). No toca STACK (v0.9
Track A) ni nube (v1.0).
