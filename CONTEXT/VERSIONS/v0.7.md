# v0.7 — Config por pestañas + archivos al workspace

## Objetivo
Ordenar la Configuración por pestañas con gestión de proyectos/archivos, y permitir subir archivos al workspace (`uploads/`) para que el agente los lea.

## Alcance (concreto)
*   Config con columna de pestañas a la izquierda (`row![tabs 180px, vertical_rule, contenido]`):
    1.  `API` — lo actual (proveedor, key, base URL, modelo, Guardar/Probar).
    2.  `Apariencia` — tema Dark/Light (aplica al instante).
    3.  `Permisos` — los 3 checkboxes del agente.
    4.  `Proyectos` — lista cada proyecto con su workspace, botón de borrado (papelera + confirmación inline) y sus archivos subidos (`uploads/`) con borrado individual. `Message::ConfigTab(Tab)`, `App::config_tab`.
*   Subir archivos (v0.7): en la fila workspace de cada proyecto del sidebar, botón `Subir` → `rfd::pick_files` en `spawn_blocking` → copia a `{workspace}/uploads/` (`Message::FilesPicked(pid, Vec<PathBuf>)`). Reglas en `workspace::upload_files`: solo archivos (no carpetas), tope 50 MB por archivo, sin sobrescribir silencioso (si existe, `nombre (2).ext`). Log `📤 a.txt → uploads/`. El agente los lee con `read_file`/`search_files` sin cambios.
*   Borrado desde Config: reutiliza `trash_dir` (papelera) y borrado de uploads limitado a `{ws}/uploads/` (guard: el path final debe quedar dentro de `uploads/`).
*   Estilo v0.7b: botón `⏻ Salir` al fondo del sidebar (`iced::exit()`); botones compactos (`padding 4`, helpers `icon_btn/primary_btn/danger_btn`); burbujas y tarjetas con `container::rounded_box`; CTAs en `button::primary`, borrados en `button::danger`; pickers con ancho fijo (140/170) contra desbordes; cero warnings de clippy.
*   Sin cambios al loop del agente.

## Paso a paso
1.  `main.rs`: `enum ConfigTab { Api, Apariencia, Permisos, Proyectos }` + `view_config` con columna de pestañas; mover secciones actuales a cada tab.
2.  Extraer `remove_project_everywhere(state, id) -> Result<String, String>` del handler actual y reusar en `ConfigDeleteProject`/`ConfirmConfigDelete` (con `config_pending_delete`).
3.  `workspace.rs`: `upload_files(ws, srcs) -> (Vec<String> ok, Vec<String> errs)` + tests (límite, no-sobrescribir, rechaza carpetas).
4.  Sidebar: botón `Subir` por proyecto con workspace + handler `FilesPicked`.
5.  Pestaña Proyectos: filas proyecto (nombre, workspace corto, `Borrar`) + lista `uploads/` (nombre, tamaño, `x`) vía `list_uploads(ws)`.
6.  Tests + docs.

## Tareas técnicas
*   Archivos: modifica `main.rs`, `workspace.rs`; sin migraciones DB.
*   `rfd::pick_files` (múltiple) en `spawn_blocking`, nunca en update directo.

## Criterio Done (estricto)
*   Config abre en pestañas; cambiar de tab no pierde lo editado sin guardar (los campos viven en el estado hasta Guardar).
*   Subir 2 archivos a un proyecto → existen en `{ws}/uploads/` y el agente los lista con `list_dir uploads`.
*   Borrar proyecto desde Config lo manda a papelera; borrar `uploads/x` solo toca ese archivo.
*   Archivo >50 MB o carpeta → error visible, nada copiado.

## Test de Funcionalidad
1. Sidebar → proyecto → Subir → elegir 2 archivos → Log `📤` y `ls {ws}/uploads`.
2. Pedir al agente "lista uploads y dime qué hay" → usa `list_dir`.
3. Config → Proyectos → borrar un upload → desaparece del disco; borrar proyecto → aparece en papelera.

## Riesgos
*   `rfd` bloquea → `spawn_blocking` como en Abrir proyecto.
*   Nombres con unicode/espacios → `PathBuf`, nunca concatenar strings.

## Dependencias
v0.6.

## Contexto / Notas
Apoyo en búsqueda web para patrones de settings con pestañas y UX de subida de archivos si hace falta.

# v0.7 Track B — Seguridad por defecto + personalización

> Mismo número de versión (v0.7 sigue abierta). Nada de lo anterior se toca.

## Objetivo B
Endurecer permisos con defaults seguros, exponer límites, describir qué pide el
agente antes de actuar, formalizar planner solo-lectura, ampliar apariencia y
dejar por escrito las políticas (`CONTEXT/POLICIES.md`).

## Alcance B (concreto)
*   **Matriz de permisos** en `config.rs` (con `#[serde(default)]` + migración
    que fuerza los nuevos a `false` aunque el toml diga otra cosa):
    `Permissions { auto_read, auto_write, auto_bash, auto_net, auto_install, extra_paths: Vec<PathBuf> }`.
    Regla: lo peligroso (red, instalación, escritura, consola, rutas externas)
    nace **desactivado** y el agente **pide permiso siempre** salvo auto explícito.
*   **Nueva tool `fetch_url`** (GET con allowlist `net_domains: Vec<String>`,
    default vacía = todo pide permiso). Sin tool de red, el agente no toca red
    (el `bash` allowlist sigue bloqueando `curl`/`wget`).
*   **Categoría `Install`**: `cargo/pip/npm/apt install…` se clasifican aparte
    (`ToolCat::Install`) y siempre piden salvo `auto_install`. Nunca auto por defecto.
*   **`extra_paths`**: lista explícita validada con `canonicalize` + deben existir.
    El guard pasa de `starts_with(workspace)` a `dentro de (workspace ∪ extra_paths)`.
    Sin esto, fuera del workspace sigue rechazado.
*   **Aprobación por categorías**: el panel muestra cada acción como
    `tool · objetivo · alcance` con badge de categoría
    (Lectura/Escritura/Consola/Red/Instalación/Externo). El detalle técnico
    completo va al Log.
*   **Planner solo-lectura**: su `llm_step` no declara tools; si un futuro cambio
    le diera una, se deniega por rol (no por config). Test que lo verifica.
*   **Límites** (nueva sub-sección en Permisos, rangos validados en UI):
    `Limits { max_iters 2–30 (def 10), max_tasks 1–5 (def 3), max_read_kb,
    bash_timeout_s, max_upload_mb }`. Las constantes actuales se leen de config.
*   **Apariencia (paquete sobrio)**: acentos elegibles (teal actual + 2 sobrios),
    escala de fuente global, densidad cómoda/compacta. Todo en `config.rs` +
    `ui/design.rs`. Sin `Theme::custom` full (se pospone a v1.x).
*   **Aviso de privacidad**: al asignar el primer workspace, aviso de que el
    código viaja al proveedor configurado + lista de paths sensibles que no se
    adjuntan al contexto LLM. Ver `CONTEXT/POLICIES.md` §2.
*   **POLICIES.md**: crear (uso, privacidad, propiedad, licencias STACK,
    consentimiento, sesión, instalación/datos) y referenciarlo en `PROJECT.md`.

## Criterio Done B
*   Config fresca → `auto_net/auto_install=false`, `extra_paths=[]` aunque el
    usuario edite el toml a mano (migración los fuerza).
*   Pedir al agente algo que requiera red/install/ruta externa → panel de
    aprobación con categoría y descripción, nada se ejecuta sin aprobar.
*   `fetch_url` a dominio no listado → pide permiso; a listado + `auto_net` → va directo.
*   Planner con tools hipotéticas → denegado por rol (test).
*   Cambiar acento/fuente/densidad aplica en vivo y persiste tras reinicio.
*   `cargo test` + `cargo clippy --all-targets` verdes, sin regresiones v0.1–v0.6.

## Test de Funcionalidad B
1. Con todo en default, pedir "descarga X e instálalo" → 2 aprobaciones categorizadas, Log con alcance.
2. Añadir `extra_paths=["/tmp/x"]`, pedir leer fuera → denegado con mensaje claro.
3. Poner `max_iters=3`, tarea larga → el turno se corta en 3 con aviso (no loop infinito).
4. Cambiar acento + fuente + densidad, reiniciar → todo persiste.

## Riesgos B
*   `extra_paths` con symlinks → `canonicalize` obligatorio en guard y en config.
*   No romper configs v0.1–v0.6: `#[serde(default)]` + tests de migración.
