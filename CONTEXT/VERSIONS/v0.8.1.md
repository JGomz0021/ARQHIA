# v0.8.1 — Cuestionario universal (Categoría+Tipo, condicional, licencias) + import auto

> Estado: 🟢 Done (implementada; `cargo test` 112/112 OK, 3 ignorados; `cargo clippy --all-targets` 0 warnings; `grep TipoProyecto` limpio en `src/`).

## Objetivo
El cuestionario deja de asumir "siempre una app desde cero": primero pregunta **qué tipo de software se va a producir** (categoría + tipo: app, framework, lenguaje, OS, automatización…), adapta las preguntas siguientes a esa familia sin redundancias, distingue licencia de facturación, y si la carpeta ya tiene código, la IA lo lee y **solo pregunta lo que falta** para el CONTEXT.

## Alcance (concreto)

### A. Taxonomía Categoría → Tipo (`levels.rs`, reemplaza `TipoProyecto`)
Dos pasos nuevos tras el Nivel (`QCat` única → `QSysType` filtrada por cat):

* **Aplicación** (la usa una persona): App web, App móvil, App escritorio, CLI/Herramienta, Juego, Bot conversacional.
* **Servicio/Backend** (corre en servidor): API/Backend, Microservicio, Servidor/Daemon, Base de datos/Middleware.
* **Librería/Ecosistema** (se consume como código o dentro de un host): Framework/Librería/SDK, Plugin/Extensión, Motor/Engine, Plantilla/Starter.
* **Sistema** (corre la máquina): Lenguaje/Runtime/Compilador, OS/Distro, Kernel/Módulo, Driver/Firmware, Contenedor/VM/Emulador, Utilidad de sistema.
* **Automatización** (hace trabajo solo): Script, Pipeline CI/CD, IaC/Despliegue, Integración/Webhook, Job programado/RPA, Agente autónomo.
* **Datos/IA**: Pipeline ETL/Dataset, Modelo ML, Agente LLM/RAG.

`TipoProyecto` (9 valores app-céntricos) se retira; `Answers { cat: Categoria, sys: SysType }`. `TipoProyecto::ALL` y sus tests se eliminan (`grep` debe quedar limpio).

### B. Dedup (qué desaparece o cambia)
* `TipoProyecto::AppWeb/AppEscritorio/AppMovil` ↔ `Plataforma::Web/Escritorio/Móvil`: solapaban. Nuevo modelo: `SysType` = **qué es**, `Plataforma` = **dónde corre** (con defaults pre-marcados por tipo pero editables; ej. API → Servidor/Nube).
* `Facturación` (suscripciones/pago/api/…) solo aplica a App/Servicio. Resto → **`Licencia`** (`MIT, Apache-2.0, GPL-3.0, Uso interno`; aviso visible si GPL; `Uso interno` nunca sube a nube — enlaza con v0.9 Track B).
* `Estilo visual`/`UI/UX` solo si el tipo tiene UI (App, Juego, Motor con editor); nunca a Driver/Pipeline/Script.
* `Stack` no se pregunta a Principiante; a Sistema se pregunta como "lenguaje de implementación + target".

### C. Matriz condicional (base común + familia)
Base común siempre (6): `nombre, descripcion, objetivo, funcionalidades, cat, sys_type`.
Después, por familia (2–4 preguntas, picks/checkboxes nunca bloquean, vacío = "(sin especificar)"):

| Familia | Preguntas propias |
|---|---|
| App | `ui_ux` + `estilo+ref` (si UI) + `plataformas` multi (pre-marcada) + `licencia/facturación` |
| Servicio | `endpoints/recursos` (area) + `api_style` (REST/gRPC/GraphQL) + `auth` (none/JWT/OAuth/API-key) + `escala/SLA` + `plataforma=Servidor` default + `stack` multi |
| Librería | `api_publica` (area) + `semver/compat` (pick) + `lenguaje target` (multi reducido) + `ejemplos/docs` (area) + `licencia` |
| Sistema | `arch target` (multi: x86_64/aarch64/embebido) + `arranque/hw` (area) + `compat` (area) + `licencia` |
| Automatización | `trigger` (cron/manual/webhook/CI) + `inputs/secretos` (area) + `idempotencia/retry` + `dónde corre` (local/CI/nube) + `stack` simple |
| Datos/IA | `dataset/fuente` + `pipeline` + `modelo/eval` (3 areas cortas) + `stack` |

Wizard dinámico: `total = 1 (nivel) + 2 (cat+tipo) + 4 (gen) + N (familia) + 1 (IA)`. `total_steps(level, sys)` y `step_question` se recalculan; se acabó el fijo 9/11/12.

### D. Import auto al Abrir (proyecto ya avanzado)
En `handlers/projects.rs::FolderPicked`: si la carpeta **no está vacía** (código detectado por `list_top` o manifiestos `Cargo.toml/package.json/go.mod/pyproject/requirements/Dockerfile/.git`), no ir a wizard vacío ni a Chat directo:
1. `Task::perform(scan_import)` — reusa `analyze_workspace + context_block + code_outlines + read_context_docs`; detecta lenguaje, entrypoints, tests, docs existentes y **campos CONTEXT que faltan** (gap vs plantilla PROJECT/SPECS).
2. Abrir cuestionario en modo `Import`: banner "Detectamos Rust + 42 archivos; README sí / SPECS no", `Answers` pre-rellenadas (nombre=carpeta, stack/plataformas inferidas) y solo pasos gap + 3–5 preguntas IA de huecos (`ai.rs::import_gap_prompt`, fallback estático sin provider).
3. `Finish` hace merge: `ensure_project_layout` + `save_project_docs` **sin borrar `Project/`** (idempotente). `QCancel` en import no borra carpeta (distinto de `q_owns_project`).

### E. Plantillas
`templates.rs`: `SPECS.md` con secciones por **familia** (no por nivel): `## Tipo de sistema` (cat + tipo), más las secciones de la matriz que apliquen; `PROJECT.md`: alcance con cat+tipo+plataformas; `CONTEXT.md`: nota de origen (`desde cero` vs `importado de código existente`).
