# v0.8.1 — Cuestionario profundo (tipo, multi-opción, presets)

## Objetivo
Profundizar el cuestionario de v0.8 sin alargarlo en exceso: separar **tipo
de proyecto** de **plataforma**, convertir plataforma y stack en **selección
múltiple**, y guiar estilo (Principiante) y arquitectura (Avanzado) con
**presets + texto libre**. Facturación suma `Publicidad` y `Freemium`.

## Alcance (concreto)

### A. Nuevas listas (`questionnaire/levels.rs`, reemplazan §A de v0.8)
*   **`TipoProyecto`** (Intermedio/Avanzado, única): `App web`, `API/Backend`,
    `Framework/Librería`, `App escritorio`, `App móvil`, `CLI/Herramienta`,
    `Juego`, `Bot/Agente`, `Otro`.
*   **`Plataforma`** (todos, **múltiple**): `Web`, `Escritorio`, `Móvil iOS`,
    `Móvil Android`, `Servidor/Nube`, `Embebido/IoT`, `Multiplataforma`.
*   **`StackOpt`** (Intermedio/Avanzado, **múltiple**): `Rust`, `Python`,
    `JS/TS`, `Go`, `Java/Kotlin`, `C/C++`, `C#`, `PHP`, `Ruby`, `Swift`,
    `Otro`, `A decidir`.
*   **`ArqPreset`** (Avanzado, preset + detalle): `Monolito`, `Por capas`,
    `Hexagonal`, `Microservicios`, `Guiada por eventos`, `Serverless`,
    `A decidir`.
*   **`EstiloPreset`** (Principiante, preset + referencia): `Minimalista`,
    `Gamer`, `Corporativo`, `Infantil/juguetón`, `Retro`, `Oscuro elegante`,
    `Otro`.
*   **`Facturacion`** suma `Publicidad` y `Freemium` (6 opciones, única).

### B. Preguntas por nivel (reemplazan el bloque por nivel de v0.8)
*   **Principiante** (3): `estilo` (preset + referencia) → `plataformas`
    (multi) → `facturacion`. Sin conceptos de código.
*   **Intermedio** (5): `ui_ux` → `tipo` → `plataformas` (multi) → `stack`
    (multi + detalle) → `facturacion`.
*   **Avanzado** (6): como Intermedio + `arquitectura` (preset + detalle).
*   Wizard total: Principiante 9, Intermedio 11, Avanzado 12 (+ paso IA).

### C. Modelo y UI
*   `Answers`: `plataformas: Vec<Plataforma>`, `stacks: Vec<StackOpt>`,
    `tipo`, `estilo` + `estilo_free`, `arq` + `arquitectura` (detalle).
    Vacío = "(sin especificar)": picks y checkboxes **nunca bloquean**.
*   Checkboxes Iced (`checkbox(...).on_toggle`) con mensajes
    `QPlataformaToggled` / `QStackToggled`; picks simples para
    tipo/estilo/arq/facturación.
*   `SPECS.md`: `## Tipo de proyecto` (Inter/Avanz), plataforma y stack
    como listas, `## Estilo visual` = preset + referencia, `## Arquitectura`
    = preset + detalle. `PROJECT.md`: alcance con tipo + plataformas.

## Paso a paso
1.  `levels.rs`: nuevos enums + `QKind::{PickTipo, PickEstilo,
    MultiPlataforma, MultiStack, PickArq}` + preguntas por nivel.
2.  `mod.rs`: `Answers` multi + `toggle_*` + `level_extras`/`clear_level`.
3.  `events.rs` + `handlers/questionnaire.rs`: nuevos mensajes, quitar los

4.  `views/questionnaire.rs`: checkboxes + preset+detalle.
5.  `templates.rs`: secciones por nivel con listas.
6.  Tests: listas amplias, toggles, docs por nivel, totales 9/11/12.
7.  Docs: este archivo + índices + `PROJECT.md` §7.2/§10/§13 + `HECHO.md`.

## Criterio Done (estricto)
*   Cada nivel muestra sus preguntas (tipo solo Inter/Avanz, arq solo
    Avanzado, estilo con lista en Principiante).
*   Plataforma/stack permiten varias marcadas; desmarcar deja vacío válido.
*   `SPECS.md` de cada nivel trae sus secciones con listas y presets.
*   `cargo test` + `cargo clippy --all-targets` verdes.
