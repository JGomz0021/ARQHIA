# v0.6 — Orquestador + permisos + subagentes (2 generadores + auditor)

## Objetivo
Mejorar el agente: más tools, petición de permisos con modal, y crear el agente principal orquestador + subagentes (2 generadores de código y 1 auditor).

## Alcance (concreto, implementado)
*   Permisos: cada lote de tool calls se clasifica (`read/list/search`→lectura, `write/edit/delete`→escritura, `bash`→consola). Lo no automático abre panel `🔐 El agente pide permiso para: • tool args + [Permitir][Denegar]`. Config `permissions: { auto_read=true, auto_write=false, auto_bash=false }` con 3 checkboxes (persisten en `config.toml`). Denegar inyecta `⛔ denegado` al LLM y sigue sin ejecutar.
*   Nueva tool: `search_files(query, dir) -> path:línea` (walkdir, máx 20 hits, salta `target/.git`, `ToolCat::Read`). `cargo check/test` se cubren vía `bash` (sin wrappers dedicados).
*   Orquestador (driver paso a paso en `main.rs` + primitivas en `agent/mod.rs`):
    *   `plan_tasks()` (1 llamada sin tools) → `Vec<WTask{desc, files}>` JSON, máx 3, fallback 1 tarea.
    *   `llm_step()` (un paso, no ejecuta) + `exec_calls()` + `denial_msgs()` por provider.
    *   Workers generadores secuenciales (2 máx por plan; paralelo con `join!` queda para después por los modales de permiso), cada uno con system propio + `AGENTS.md`.
    *   `audit_workspace()` (LLM solo-lectura + `bash cargo check` si hay Cargo.toml) → `{workspace}/CONTEXT/TEMP.md`; si hay issues, 1 pasada de fixes y re-auditoría final.
*   `AGENTS.md`: plantilla escrita al iniciar el turno si falta; su contenido entra a los prompts worker.
*   UI: checklist `☑/▶/☐` de tareas sobre el Log + preview de issues del TEMP.md en el Log.

## Paso a paso
1.  `tools::search_files` + `ToolCat` + schemas en ambos providers + tests.
2.  `Permissions` en `config.rs` (serde defaults para no romper configs viejas) + 3 checkboxes en Config.
3.  `agent/mod.rs`: `PendingCall/StepOutcome`, `llm_step`, `exec_calls`, `denial_msgs`, `plan_tasks` (+`parse_tasks`), `simple_chat`, `audit_workspace`, `AGENTS_TEMPLATE` + `ensure/read_agents_md`. `run_turn` reescrito sobre las primitivas (lo usa el E2E).
4.  `main.rs`: máquina de estados `AgentPlan → AgentLlm → (AgentExecDone | Approve/Deny) → … → AgentAudit → finish`, `Driver` + `OrchTask`, panel de permisos, checklist, escritura de TEMP.md.
5.  Tests: `parse_tasks` (plano/fences/inválido), `temp_has_issues`, `worker_system`, `search`, `category` + E2E ignorado `orchestrator_e2e` (planner→workers→auditor contra API real).

## Tareas técnicas
*   Archivos: modifica `agent/mod.rs`, `agent/tools.rs`, `main.rs`, `config.rs`.
*   Workers secuenciales (el paralelo real con `join!` queda pendiente: los modales de permiso lo impiden por ahora).

## Criterio Done (estricto)
*   `write` con permiso en manual abre panel; Permitir ejecuta, Denegar cancela sin ejecutar (verificable en el Log). `Denegar y no preguntar más` silencia esa tool el resto del turno.
*   "crea a.txt y b.txt" se divide en 2 tareas visibles `☐→▶→☑` y ambos archivos existen.
*   Auditor escribe `CONTEXT/TEMP.md`; con issues hace 1 pasada de fixes. Botón `📝 TEMP` muestra el archivo en la UI.
*   `AGENTS.md` se crea solo y entra a los prompts worker; `ESPEC.md` también se inyecta (planner + workers).
*   `⏹ Detener` cancela el turno en cualquier fase sin corromper el siguiente (resultados tardíos ignorados por generación).
*   Borrar proyecto mueve su carpeta a `~/.local/share/arqhia/papelera/` en vez de borrarla.
*   Modelos locales sin function calling degradan a chat plano en vez de romper el turno (400 con "tool" → retry sin tools).

## Test de Funcionalidad
1. Pedir "crea src/a.rs y src/b.rs con hello", aprobar 2 writes, verificar ambos existen.
2. Introducir `let x = ;` en a.rs, pedir "audita", verificar TEMP.md contiene el error.
3. Denegar un `bash cargo test`, verificar no se ejecuta.

## Riesgos
*   Races FS entre workers → asignar archivos disjuntos + `Mutex` por path.
*   LLM ignora formato Task → validación JSON estricta + reintento 1 vez.

## Dependencias
v0.5 (ESPEC.md) + v0.3 (tools base).
