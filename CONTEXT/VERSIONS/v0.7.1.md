# v0.7.1 — Agente eficiente + Modos Chat/Plan/Work

> **Estado: 🟢 Done (probada en GUI y revisada).**

## Objetivo
Frenar el consumo de tokens del agente (casos reales de ~200k sin hacer casi
nada) y hacer explícitos los modos de trabajo. Sin renumerar: entra entre
v0.7 y v0.8.

## Alcance (concreto)

### A. Modos (movido desde v0.8 Track B)
*   `Mode { Chat, Plan, Work }` por chat, persistido (migración
    `chats.mode TEXT DEFAULT NULL`; NULL = legacy).
*   **Default: Chat.** Sin ambigüedad: con o sin workspace se empieza en Chat
    y se sube a Plan/Work explícitamente.
*   **Visibilidad obligatoria**: badge del modo siempre en el header del chat
    (tono Accent si no es Chat) + selector segmentado `Chat | Plan | Work` en
    el composer. Imposible no saber en qué modo se está.
*   **Plan**: solo `plan_tasks` → `CONTEXT/PLAN.md` + checklist + botón
    **"Ejecutar plan"** (pasa a Work). Sin tools por construcción.
*   **Work**: orquestador actual bajo permisos/límites v0.7.
*   **Atajos** (adelantados aquí porque sin ellos el cambio de modo es torpe):
    `Ctrl+N` nuevo chat, `Ctrl+1/2/3` modos, `Ctrl+O` abrir proyecto, `Ctrl+,`
    configuración, `Esc` cerrar menús. Apartado **Atajos** de solo lectura en
    Config. Sin Tab para modos (colisiona con foco).

### B. Lectura/búsqueda por coincidencias (nuevo núcleo)
*   **`search_files` v2**: bloques de coincidencia con 3 líneas de contexto
    (`path:línea: [ctx] match [ctx]`), máx 20 bloques, ranking (nombre de
    archivo > contenido; hits del mismo archivo agrupados). Nunca el archivo
    completo.
*   **`read_file` paginado**: params `offset`/`limit` (def: primeras 200 líneas);
    respuesta `líneas X–Y de Z total`. El modelo pide páginas.
*   **Nueva tool `get_file_outline`**: solo firmas (funciones, structs,
    imports) para decidir *qué* leer. Flujo esperado: outline → search → read.
*   **Ignorados por defecto** en search/list recursivo: `target/`, `.git/`,
    `node_modules/`, `*.lock`, binarios. Sin confirmaciones: la optimización
    sustituye al aviso.

### C. Optimización de tokens
*   **Historial acotado**: ventana últimos 20 mensajes (configurable) en vez
    de 500; lo viejo colapsa con marcador.
*   **Outputs acotados**: últimos K resultados en `raw`, resto `[omitido]`;
    **caché de lecturas por turno** (mismo archivo no se relee).
*   **System adelgazado**: ESPEC/AGENTS.md una vez por worker como mensaje de
    contexto, no en cada step.
*   **Parada temprana**: 2 steps sin cambios o calls idénticas → fin del worker.
*   **Límite configurable, default SIN límite** (`Limits.max_tokens_turn = 0`
    = ilimitado); si >0, al 80% compacta y al 100% para con mensaje.
*   **Contador discreto en el Log**: badge `~12k tokens este turno` (estimador
    `chars/4`, documentado como aproximado ±30% según tokenizer). Sin panel.

### D. Referencia externa
*   Revisar el repositorio de **opencode** (opensource, `github.com/sst/opencode`)
    como guía: diseño de tools (matches, paginación, truncados), loop de agente,
    subagentes y cómo exponen consumo/actividad. Igual que v0.6 usó
    aider/swe-agent como referencia, v0.7.1 usa opencode. Adaptar patrones, no
    copiar código.

## Tareas técnicas
*   Archivos: `db.rs` (migración), `agent/tools.rs`, `agent/mod.rs`,
    `app/*` (modo, driver, presupuesto), `views/` (badge, selector, badge Log),
    `config.rs` (ignores, `max_tokens_turn`).
*   Sin cambios a providers ni a STACK.

## Criterio Done (medible)
*   "Revisa este proyecto" en Plan: **1 llamada**; en Work con defaults:
    outline+search+reads paginados y consumo **< 25% del baseline** medido antes.
*   Cambiar de modo cambia badge + capacidades reales (en Plan no se ejecuta);
    modo persiste tras reinicio; default de un chat nuevo es Chat.
*   Los 5 atajos funcionan y aparecen en Config.
*   Tests: ranking de matches, paginación, outline, caché, parada, modos,
    default Chat. `cargo test` + `cargo clippy --all-targets` verdes.

## Test de Funcionalidad
1. Chat nuevo → badge dice Chat aunque haya workspace.
2. `Ctrl+2` → Plan; "revisa el proyecto" → `PLAN.md` existe, disco intacto, 1 llamada.
3. Work sobre repo grande → Log muestra badge de tokens, `target/` ignorado.
4. Poner `max_tokens_turn=5000`, tarea larga → para al 100% con mensaje.

## Riesgos
*   Atajos en Iced: no robar teclas escribiendo en inputs; `Esc` previo si hace falta.
*   `chats.mode` NULL legacy → tratar como Chat, nunca como error.
*   El estimador `chars/4` subestima código denso: documentar, no prometer exactitud.
