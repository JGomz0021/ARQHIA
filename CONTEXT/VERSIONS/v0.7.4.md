# v0.7.4 — Chat UX + modelos con nombre

## Objetivo
Pulir la experiencia de chat y el manejo de modelos sin tocar el cuestionario ni
la estructura de proyecto de v0.8. **Versión intermedia** (como v0.7.1–v0.7.3)
para no sobrecargar v0.8, que ya asume cuestionario + estructura + onboarding +
sesiones (`VERSIONS/v0.8.md` §E).

## Alcance (concreto)

### A. Modelos guardados con nombre (perfiles)
Hoy solo hay un modelo por provider. Se añaden **perfiles de modelo** con un
**nombre visible** elegido por el usuario:

*   `ModelProfile { id, nombre, provider, base_url, api_key, model, reasoning_effort }`
    en `config.toml` (lista `model_profiles` + `active_profile`).
*   El **nombre** es lo que aparece en el selector de modelo (Config → API y en
    el composer), no el id crudo del modelo.
*   CRUD: `Guardar como perfil`, `Renombrar`, `Duplicar`, `Borrar`, `Activar`.
*   Mensajes `Profile*` en `events.rs`, staging en `state.rs`, brazos en
    `handlers/config.rs` y `.on_press` en `views/config_view.rs`.
*   Migración: sin perfiles, el provider/modelo activo actual se ofrece como
    `"Perfil por defecto"` (no rompe configs viejas).

### B. Utilidades de chat
*   **Título por IA:** al primer turno de un chat, una llamada corta (mismo
    provider, sin tools) propone un título de 3–5 palabras; si falla, cae al
    primer mensaje del usuario (comportamiento actual). Botón `Regenerar título`.
*   **Undo:** deshacer la última acción (envío o borrado de mensaje) con `Ctrl+Z`.
    Pila por chat en memoria (alcance acotado: 1 paso).
*   **Copiar chat:** duplicar la conversación completa a un chat nuevo,
    conservando proyecto y modo.
*   **Nuevo chat desde un mensaje:** bifurcar desde el mensaje N (nuevo chat con
    el historial hasta N) para explorar una rama sin perder el hilo original.
*   **Hora y día:** cada mensaje muestra fecha/hora; se persiste
    `messages.created_at` (migración aditiva).
*   **Reintentar con icono:** el reintento del último turno fallido pasa a un
    icono `↻` junto al mensaje (mantiene `RetryLast`).
*   **Citar fuentes:** cuando el agente use `fetch_url`, el mensaje muestra las
    URLs consultadas como bloque `Fuentes` (clicables) y el modelo puede
    referenciarlas con marcadores `[1]`, `[2]`…

## Paso a paso
1.  `config.rs`: `ModelProfile` + `active_profile` + migración + tests.
2.  `events/state/handlers/config/views/config_view`: CRUD de perfiles; el
    selector de Config y composer muestran el `nombre`.
3.  `db.rs`: `messages.created_at` (migración aditiva) + `copy_chat` +
    `branch_chat` (duplicar filas hasta el mensaje N).
4.  UI chat (`views/chat.rs`): timestamps, undo (`Ctrl+Z`), copiar, bifurcar,
    reintento con icono y bloque `Fuentes`.
5.  `agent/llm`: título por IA (1 llamada, fallback) + captura de URLs de
    `fetch_url` para las fuentes.
6.  Tests: perfiles roundtrip/activo, `copy_chat`/`branch_chat`, timestamps,
    undo, fuentes.

## Tareas técnicas
*   Archivos: `config.rs`, `db.rs`, `llm/mod.rs`, `agent/mod.rs`,

    `app/handlers/{chat,config,agent}.rs`, `views/{chat,config_view,sidebar}.rs`,
    `titles.rs`.
*   Sin cambios a providers de red ni STACK. Migraciones de DB aditivas.

## Criterio Done (estricto)
*   Guardar 2 perfiles con nombres distintos y alternarlos desde el selector del
    composer y de Config; persisten tras reiniciar.
*   Un chat nuevo recibe título por IA (o fallback al primer mensaje).
*   `Undo` restaura el último envío/borrado; `Copiar chat` duplica;
    `Nuevo chat desde mensaje` bifurca en N.
*   Cada mensaje muestra fecha/hora; el reintento es un icono; tras un
    `fetch_url` el chat muestra `Fuentes` clicables.
*   `cargo test` + `cargo clippy --all-targets` verdes.

## Test de Funcionalidad
1.  Crear perfiles "Rápido" (gpt-4o-mini) y "Potente" (claude) → alternar y ver
    el nombre en el composer; reiniciar y comprobar persistencia.
2.  Chat nuevo → título por IA; `Regenerar título` lo cambia.
3.  Enviar 3 mensajes → `Ctrl+Z` quita el último; `Copiar chat` crea duplicado;
    `Nuevo chat desde mensaje` en el 2.º crea uno con 2 mensajes.
4.  Ver fecha/hora por mensaje; reintentar con `↻`.
5.  Pedir al agente que consulte una URL (`fetch_url`) → bloque `Fuentes`.

## Riesgos
*   Coste del título IA → 1 llamada muy corta + fallback local; sin provider no
    bloquea.
*   Undo en memoria vs DB → alcance acotado a 1 paso para no complicar la
    persistencia; no borra de la DB hasta confirmar.
*   `branch_chat`/`copy_chat` duplican filas → operación transaccional y tests.
*   API keys en perfiles → se guardan en `config.toml` como hoy; no se registran
    en logs.
