# v1.0.1 — MCP avanzado (pestaña, resources/prompts, item `MCP`, auth HTTP)

## Objetivo
Sobre el MCP mínimo (v0.9.3), darle UI y capacidades completas: administración sin reiniciar, `resources`/`prompts`, marketplace vía STACK e histórico remoto con auth.

## Alcance (concreto)
*   Pestaña `Config → MCP`: servidores on/off, tools on/off por servidor, estado (conectado/error), últimas líneas de log, botón Probar. Sin reiniciar.
*   `resources/list/read` inyectables como contexto; `prompts/get` como plantillas de turno.
*   Marketplace STACK: configs de servidor como items con etiqueta `MCP` (instalar = copiar config; el binario lo pone el usuario, con el consentimiento del código).
*   HTTP remoto: headers/auth por servidor (token en config 600, nunca en logs), reconnect con backoff.

## Paso a paso
1.  Pestaña MCP (`ConfigTab::Mcp` + card + dispatch) + estado/log/probar + tests de vista.
2.  `mcp.rs`: `resources/list/read` + `prompts/get` + tests contra stub.
3.  Item STACK `MCP`: badge + `Instalar` (copia config validada) + test con mock.
4.  Auth HTTP por servidor (token 600, sin fugas) + reconnect backoff + test.
5.  `cargo test mcp` + `cargo clippy`.

## Tareas técnicas
*   Modifica: `config.rs` (`[mcp]` avanzado), `src/mcp.rs` (resources/prompts/auth), `agent/tools.rs` (schemas extra), `app/{events,state,handlers/*}` (toggle sin reiniciar), `views/{config_view,chat}` (pestaña + badge).
*   Sin crates nuevos. Sin migración DB.

## Criterio Done (estricto)
*   Desactivar un servidor en la pestaña → sus tools desaparecen del siguiente turno sin reiniciar.
*   `resource` inyectado como contexto visible en el turno.
*   Item `MCP` del STACK → instala config usable; token auth sin fugas en logs.
*   `cargo test` + `cargo clippy --all-targets` verdes.

## Test de Funcionalidad
1.  Stub con resource `docs`: pedir "usa docs de MCP" → contexto inyectado.
2.  Prompt `plan-x` del servidor → plantilla aplicada al turno.
3.  Desactivar servidor → siguiente turno sin sus tools.
4.  Item `MCP` del STACK → instala y conecta.

## Riesgos
*   Resources gigantes → tope 8KB con aviso (igual que skills).
*   Token en logs → revisión `grep token` en tests.

## Dependencias
v1.0 (release estable con MCP mínimo v0.9.3). No toca Pro (v1.1).
