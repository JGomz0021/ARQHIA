# v0.7.2 — Git nativo + puerta de calidad

## Objetivo
Convertir Git en configuración de primera clase: ARQHIA inicializa un repo por
workspace, trabaja siempre en una rama dedicada (`ARQHIA`), deja al usuario
decidir la autonomía del agente (solo lectura / commit local / commit y push) y
bloquea lo destructivo. Además, endurecer la verificación del auditor
(`cargo test` + `cargo clippy`) y hacer que el auto-commit dependa de que la
verificación pase. Todo pensado para poder empezar el autodesarrollo (dogfooding)
sin arriesgar el código propio.

## Alcance (concreto)

### A. Configuración de Git (`config.rs`)
Nuevo `GitConfig` dentro de `AppConfig` con `#[serde(default)]` (migración
automática, igual que `Permissions`):

*   `enabled: bool` (def `true`) — "siempre se inicia git".
*   `auto_init: bool` (def `true`) — `git init` si el workspace no es repo.
*   `base_branch: String` (def `"main"`).
*   `work_branch: String` (def `"ARQHIA"`).
*   `branch_mode: BranchMode { Single, PerTask }` (def `Single`; `PerTask` =
    `arqhia/<tarea>`, reservado para más adelante).
*   `autonomy: GitAutonomy { ReadOnly, CommitLocal, CommitAndPush }`
    (def `CommitLocal`).
*   `push_enabled: bool` (def `false`) — push pide aprobación salvo que se
    active y la autonomía sea `CommitAndPush`.
*   `remote: String` (def `"origin"`).
*   `push_branch: String` (def `""` = igual que `work_branch`).
*   `protected: Vec<String>` (def `["main", "master"]`).
*   `author_name` / `author_email` (`""` = usar identidad global de git).

Validación (`validated()`): recorta nombres de rama/remoto (sin espacios, sin
`..`), y **rechaza que `work_branch` esté en `protected`**. `main`/`master`
nunca se tocan.

### B. Módulo `git.rs` (dominio, testeable)
*   `is_repo(ws)`, `current_branch(ws)`, `remotes(ws)`, `status_short(ws)`,
    `is_clean(ws)`.
*   `init_repo(ws, base_branch)` — no reinicia si ya hay `.git`.
*   `ensure_work_branch(ws, &GitConfig)` — crea/usa `work_branch` y hace
    checkout; nunca sobre `protected`.
*   `commit_all(ws, msg, author)` — `git add -A && git commit`; si el árbol
    estaba sucio **antes** del turno, no auto-commitea (evita barrer ediciones
    manuales ajenas).
*   `push(ws, remote, branch)` — no interactivo (`GIT_TERMINAL_PROMPT=0`),
    con timeout, error legible si no hay credenciales.
*   `diff_stat(ws)` para el auditor.
*   Tests con `tmpdir` + `git init`: crear rama, proteger base, rechazar
    destructivos, no-op sin repo.

### C. Política del agente (`agent/tools.rs`)
`ExecPolicy` recibe `GitConfig` y clasifica los comandos `git`:
*   **Lectura** (`status`, `diff`, `log`, `show`, `branch`, `rev-parse`):
    auto si `auto_read`.
*   **Escritura local** (`init`, `add`, `commit`, `stash`): auto si
    `autonomy >= CommitLocal`; si no, panel de aprobación.
*   **Red** (`push`, `fetch`, `pull`): auto solo si
    `autonomy == CommitAndPush && push_enabled`; si no, panel (categoría
    `GitPush`).
*   **Bloqueado siempre**: `push --force`, `reset --hard`, `clean`, `rebase`,
    `config`, `remote add/remove`, y commit directo sobre `protected`.
*   Nuevas categorías `ToolCat::Git` / `ToolCat::GitPush` para el panel
    (`git · rama · alcance`).
*   Allowlist ampliada: `cargo clippy`, `cargo fmt`.

### D. Orquestador (`app/orchestrator.rs`, `app/projects.rs`)
*   Al crear/abrir proyecto con `git.enabled`: `git::init_repo` +
    `ensure_work_branch` (detecta repo existente, no reinicia).
*   Al arrancar un turno Work: `git::ensure_work_branch` → Log
    `🌿 git: rama ARQHIA`.
*   Al cerrar un turno con éxito: auto-commit `"ARQHIA: <resumen>"` si
    `autonomy >= CommitLocal`; push solo si `CommitAndPush && push_enabled`
    (y con aprobación si no está auto).
*   El auditor incluye `git diff --stat` en el contexto de `TEMP.md`.

### E. Puerta de calidad (auditor)
*   `audit_workspace` ejecuta `cargo check` + `cargo test` +
    `cargo clippy --all-targets` con timeout ampliado (los tests/clippy pueden
    tardar más de 30s).
*   `TEMP.md` solo dice "SIN ISSUES" si los tres pasan; si no, incluye el fallo
    concreto y dispara la pasada de fixes.
*   **El auto-commit solo ocurre si la verificación pasó** (no se commitea rojo).

### F. UI Configuración
*   `ConfigTab::Git` (nueva pestaña). `view_config_git` con 3 cards:
    1.  **Repositorio**: enabled, auto_init, rama base, modo (`ARQHIA` única /
        por-tarea), remoto, rama de push.
    2.  **Autonomía del agente**: pick_list `Solo lectura / Commit local /
        Commit y push`, toggle `Permitir push a GitHub`, autor (nombre/email).
    3.  **Estado del workspace activo**: rama actual, remoto, nº de cambios y
        botón `Inicializar git` si no es repo (Task async).
*   Mensajes `Git*` en `events.rs`, staging de campos en `state.rs`, brazos en
    `handlers/config.rs` y persistencia con `config.save()`.

## Criterio Done (estricto)
*   Pestaña **Git** visible; defaults `ARQHIA`; persiste tras reinicio.
*   Crear un proyecto → repo con rama `ARQHIA` y `main` protegida.
*   En Work: `git status`/`commit` funcionan; `push` pide permiso;
    `push --force` y `reset --hard` bloqueados.
*   Turno exitoso → commit con resumen; **no** commitea si `cargo test`/`clippy`
    fallan.
*   `cargo test` + `cargo clippy --all-targets` verdes (sin regresiones
    v0.1–v0.7.1).

## Test de Funcionalidad
1.  Config → Git: activar/desactivar, cambiar rama de trabajo, autónomía; reiniciar
    y verificar persistencia.
2.  Crear proyecto nuevo → `git -C {ws} branch --show-current` = `ARQHIA`.
3.  Pedir al agente "haz un cambio y commitea" en Work → commit en `ARQHIA`,
    Log `🌿`; luego "haz push" → panel de aprobación.
4.  Forzar un fallo de test y cerrar turno → sin commit, `TEMP.md` con el fallo.

## Riesgos
*   Push con credenciales → no interactivo + timeout; error claro en el Log.
*   `git add -A` en workspace=raíz podría incluir cambios ajenos → guarda
    anti-sucio (solo auto-commit si el árbol estaba limpio al iniciar).
*   Espacios/caracteres raros en nombres de rama → validación al guardar.
*   `main` protegida: `ensure_work_branch` cambia a `ARQHIA` antes de escribir.
