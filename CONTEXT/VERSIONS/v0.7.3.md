# v0.7.3 — Bucle de estabilidad (analista → workers → auditor → fix hasta verde)

## Objetivo
Cerrar el flujo de trabajo completo antes del STACK:

```
petición > orquestador > analista (contexto/specs/código) > planner > workers
        > auditor > TEMP > loop hasta verde > commit (rama ARQHIA) > push (opcional)
```

Convierte la auditoría actual (1 sola pasada de fixes) en un **bucle sin tope**
que repite `auditor → fix` hasta que la puerta de calidad quede verde, y solo
entonces auto-commitea. Así ARQHIA puede modificar su propio código
(dogfooding) sin arriesgar la rama base y sin commitear en rojo.

## Alcance (concreto)

### A. Paso de análisis dedicado (`agent/mod.rs` + `handlers/chat.rs`)
Nuevo `agent::analyze_workspace(provider, cfg, workspace, pedido) -> Result<String, String>`:
*   Una sola llamada LLM **sin tools** (mismo camino que `simple_chat`).
*   Entrada (recortada por archivo, ~1500 chars):
    *   `workspace::context_block(ws)` (árbol + archivos).
    *   Docs reales de `CONTEXT/`: `ESPEC.md` (o `PROJECT.md`/`SPECS.md`/`CONTEXT.md`
        cuando existan en v0.8), `VERSIONS.md`, `TEMP.md` previo y `PLAN.md` si hay.
    *   Outlines de código (firmas, no cuerpos) vía la lógica de `get_file_outline`
        sobre los `.rs`/fuentes principales del workspace.
    *   El pedido del usuario.
*   Salida: **brief** estructurado en Markdown (estado actual, restricciones,
    archivos que toca, riesgos). Se pasa al `planner` como contexto adicional.
*   Fallback: sin provider, error o timeout → se usa `context_block` crudo y el
    flujo continúa (el análisis nunca bloquea el turno).
*   Se registra en `CONTEXT/ANALYSIS.md` (trazabilidad) y se lee en cada Plan/Work.

### B. Loop hasta verde (`handlers/agent.rs`)
Reemplaza `fix_cycle < 1` por `fix_cycle < max_fix_cycles` con
`max_fix_cycles == 0 ⇒ ilimitado`.
*   `AgentAudit` con issues → worker de fixes → **re-auditoría** → si sigue con
    issues → otro ciclo. Sin tope por defecto (decisión de producto).
*   Frenos reales que ya existen y no se tocan: botón `Detener`
    (`agent_gen` invalida lo en vuelo), `Limits.max_tokens_turn` y parada
    temprana por calls idénticas.
*   Nuevo `Limits.max_fix_cycles` (0 = ilimitado, default) para capar sin
    recompilar; al alcanzar el tope con issues: se reporta, `TEMP.md` conserva
    el fallo y **no** se commitea.
*   `TEMP.md` incluye contador de ciclo y `git diff --stat` (de v0.7.2).
*   Log/UI: línea `↻ ciclo N: M issues` y cierre
    `✅ estable tras N ciclos -> commit <hash>`.

### C. Commit solo al cerrar verde (reubica v0.7.2 §D)
*   El auto-commit del turno pasa a ejecutarse **solo cuando el bucle termina
    sin issues** (auditor LLM limpio + `cargo check`+`test`+`clippy` verdes).
*   Turno detenido por el usuario o cortado por presupuesto ⇒ sin commit.
*   Mensaje: `"ARQHIA: <resumen del turno>"`; push solo si
    `autonomy == CommitAndPush && push_enabled` (+ aprobación si no es auto).
*   Si no hay repo o `git.enabled == false`, el flujo continúa sin git (aviso
    en el Log).

### D. Contextos y planner
*   `plan_tasks` (Plan y Work) recibe el brief del analista además de
    `context_block` + docs; firmas actualizadas y tests de composición.
*   `worker_seed` ya inyecta el contexto una vez; se le añade el brief cuando
    exista (`CONTEXT/ANALYSIS.md`), sin duplicar en cada step.

## Paso a paso
1.  `config.rs`: `Limits.max_fix_cycles` (default 0) + clamp + validación + tests.
2.  `agent/mod.rs`: `read_context_docs(ws)` (lee `CONTEXT/*.md` con tope),
    `analyze_workspace(...)` y tests (composición del prompt, fallback).
3.  `handlers/chat.rs`: llamar al analista antes de `plan_tasks` en Plan y Work;
    guardar `CONTEXT/ANALYSIS.md`; pasar el brief al planner.
4.  `handlers/agent.rs`: loop `audit → fix` sin tope (con `max_fix_cycles`),
    contador de ciclo en `TEMP.md`, cierre verde y commit vía `git.rs`.
5.  `views` + `handlers/config.rs`: límite `max_fix_cycles` en Límites; estado
    del ciclo visible en el Log (sin panel nuevo).
6.  Docs (`PROJECT.md`, `ROADMAP.md`, `VERSIONS.md`, `HECHO.md`, `AGENTS.md`) y
    `cargo test`/`clippy --all-targets` verdes.

## Tareas técnicas
*   Archivos: `config.rs`, `agent/mod.rs`, `agent/tools.rs` (nada nuevo de
    política), `app/handlers/{chat,agent}.rs`, `app/state.rs`, `views/config_view.rs`.
*   Depende de `git.rs` y `GitConfig` (v0.7.2); sin migraciones de DB.

## Criterio Done (estricto)
*   Un turno Work con fallos forzados encadena ≥2 ciclos `fix → audit` y
    termina verde; no hay tope por defecto.
*   `TEMP.md` muestra el ciclo y el diff; el commit ocurre **solo** al quedar
    verde (verificado con un test que fuerza rojo: sin commit).
*   El analista produce `CONTEXT/ANALYSIS.md` y el planner lo usa; sin provider
    el flujo no se bloquea.
*   `Detener` y presupuesto cortan el bucle sin commitear.
*   `cargo test` + `cargo clippy --all-targets` verdes (sin regresiones
    v0.1–v0.7.2).

## Test de Funcionalidad
1.  Turno Work sobre un proyecto con un test roto a propósito → el bucle da
    ≥2 vueltas, corrige y cierra con commit; `git log` muestra el commit.
2.  Turno Work que no se puede arreglar → tras los ciclos: issues en chat +
    `TEMP.md`, sin commit (`git status` con cambios pendientes).
3.  Pulsar `Detener` a mitad del bucle → sin commit y sin resultados tardíos.
4.  Sin provider: el análisis cae a `context_block` y el turno sigue.
5.  `max_fix_cycles = 2` → se detiene al 2º ciclo con issues.

## Riesgos
*   Bucle infinito si el LLM nunca corrige → frenos: `Detener`, presupuesto de
    turno, parada temprana por calls idénticas y opción `max_fix_cycles`.
*   Analista costoso en contextos grandes → topes de chars por doc y outlines
    (firmas) en vez de cuerpos; fallback si tarda/falla.
*   Commit temprano con el árbol sucio por ediciones manuales → guarda
    anti-sucio de `git.rs` (v0.7.2): solo auto-commit si el árbol estaba limpio
    al iniciar el turno.

## Dependencias
v0.7.2 (Git + puerta de calidad). No toca v0.8; los docs `PROJECT/SPECS/CONTEXT.md`
se leerán genéricamente cuando v0.8 los cree.

## Contexto / Notas
Decisiones de producto (sesión de diseño):
*   Commit **1 por turno con el loop verde** (no por tarea, no por versión).
*   Análisis como **llamada dedicada** (brief), no solo inyección al planner.
*   Bucle **ilimitado hasta verde** por defecto; el único freno son los límites
    de tokens/pasos y el botón `Detener`.
*   Push siempre opcional: `CommitAndPush && push_enabled` + aprobación.
*   Este es el flujo previo al STACK: cuando el bucle sea estable, v0.9 añade la
    consulta al STACK como paso previo al diseño de tareas.
