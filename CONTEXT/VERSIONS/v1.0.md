# v1.0 — STACK nube + auth + updater + release estable (Linux + Windows)

> **Requiere la dependencia `WEB`** (`CONTEXT/WEB.md`) ya publicada y la
> puerta **v0.9.6 verde** (icono + instalador + tests): sin icono no hay release.
> Incluye el MCP mínimo de v0.9.3 (verificado en su E2E).

## Objetivo
Llevar el STACK a la nube, cerrar la sesión real, dar a la app un **sistema de
actualizaciones embebido (notificar + descargar)**, publicar en **Microsoft
Store** el canal Windows y dejar un release estable con backup/export.

## Alcance (concreto)

### A. STACK nube (`src/stack/cloud.rs`)
1.  `push(item_id)`: `POST {cloud_url}/stack/push {title, code, tags, lang, meta}`
    con header `Authorization: Bearer {token}`. Retorna `remote_id`.
2.  `pull(since)`: `GET /stack/pull?since=` → merge a SQLite local (upsert por
    `remote_id`, sin duplicar).
3.  `search_cloud(query, tags)`: `GET /stack/search?q=&tags=` → mismos
    `ScoredItem`; **fallback** a `stack::search` local si falla/timeout 5s, con
    indicador `Nube ○ offline`.
4.  Config → Nube: `cloud_url` (def `http://localhost:3000`), `cloud_token`
    (permisos 600), `Probar conexión`.
5.  Backend de referencia (no bloqueante): stub Axum+Postgres+S3 o **mock local**
    `~/.arqhia/cloud/{items.json}` con los 3 endpoints. El release indica cuál
    se usó, sin fingir nube real.

### B. Auth nube (Config → Nube)
*   Login con email + token del backend; el token se guarda en config local con
    permisos `600` y **nunca** aparece en logs/ESPEC/TEMP.
*   Requiere la identidad local de v0.9 como base (migra `name/email`).
*   Logout borra el token.

### C. Updater embebido (notificar + descargar)
*   Al arrancar (y cada X horas), consultar
    `{web}/updates/latest.json` (`CONTEXT/WEB.md` §4).
*   Comparar versión con **semver**; si hay más nueva, mostrar **banner en Home**:
    versión + novedades (`notes_url`) + botón `Descargar`.
*   **No auto-reemplaza** en v1.0: descarga manual desde la web. Funciona igual
    en Linux; en Windows-Store la Store actualiza sola y el aviso puede
    omitirse.
*   Firma opcional de release: el manifiesto incluye `sha256`; la app puede
    verificarlo (reutiliza `ed25519` más adelante en v1.1).

### D. Distribución Windows — Microsoft Store
*   Publicar como **MSIX** (Win32 full-trust). Registro de desarrollador
    **gratis** (flujo nuevo en `storedeveloper.microsoft.com`); verificación de
    identidad obligatoria.
*   **Microsoft firma** el paquete y gestiona las actualizaciones → sin
    certificado Authenticode propio ni SmartScreen.
*   La certificación exige **URL de privacidad y soporte** → cubiertas por
    `WEB`.
*   Validar la vía de **comercio propio** para la licencia Pro externa (v1.1);
    si no, usar el comercio de Microsoft.

### E. Backup / export (Config → Proyectos)
*   Exportar proyecto = copia autocontenida de la carpeta del workspace.
*   Backup/restore de `arqhia.db`; migraciones de esquema documentadas en
    CHANGELOG. El instalador/actualizador nunca borra `arqhia.db`,
    `config.toml` ni workspaces.

### F. Workers asíncronos (base, sin sandboxes)
*   `app/orchestrator.rs`: `state.driver: Option<Driver>` convive con
    `state.drivers: Vec<Driver>`; `start_workers_async(tasks)` lanza 2–3
    `Task::perform(llm_step)` con `Message::AgentLlm(task_idx, turn, res)`.
    Base sobre `Project/` (sin copia a sandbox): cada worker declara
    `files` disjuntos en el plan; si dos workers tocan el mismo archivo,
    el segundo espera (fallback secuencial con aviso en el Log).
*   `Limits`: `max_workers 1–3 (def 2)` en Free y Pro (v1.0 no gatea
    potencia; v1.1 sube a 8 con sandboxes). Sin `merge.rs` aún: el auditor
    final corre sobre la base tras join de workers.
*   Cancelación por `agent_gen` existente + `Detener` cancela todos los
    workers del turno (`git_turn_interrupted` → sin commit, como v0.7.3).
    Presupuesto `max_tokens_turn` compartido entre workers del turno.

### G. Skills en la nube (etiqueta `SKILL` del STACK)

*   **Tipo `skill` en el STACK**: `stack_items` con etiqueta especial `SKILL`
    (misma tabla/búsqueda de v0.9, con badge visible en la UI). El contenido
    es la carpeta serializada (`SKILL.md` + recursos; scripts incluidos como
    texto, tope 8 KB por archivo como en local).
*   **`skills::install_from_stack(id)`**: descarga, valida frontmatter y
    guarda en `skills/` global. Licencia `Uso interno` → **no instalable
    desde nube** (misma regla que el código, v0.9 Track B, con error claro).
    Juega con las mismas reglas que una local (permiso Bash existente).
*   **`skills::publish_to_stack(nombre)`**: sube una skill local como item
    `SKILL` (exige `share_cloud` + sesión v1.0, igual que el código; `Uso
    interno` ni se ofrece).
*   **UI**: badge `SKILL` en resultados del STACK + botones `Instalar` /
    `Publicar skill`; mismo consentimiento que el código (`POLICIES.md` §4).
    Offline: lo instalado en local sigue funcionando (`/skill` sin cambios).

### H. Pulido y release
1.  Fix bugs v0.7–v0.9.6 reportados (lista en `TEMP.md`).
2.  `cargo clippy -- -D warnings`, `cargo fmt --check`, `cargo test` verdes.
3.  `cargo build --release` Linux `<30MB` aprox (medido en v0.9.6), open <2s, TTFB <300ms.
4.  Icono v0.9.6 verificado en `.deb` instalado, `.desktop` y ventana/Home.
5.  Docs: `README.md`, `CHANGELOG.md` v0.1→v1.0, `VERSIONS.md` al día.
5.  Dogfooding: crear 1 proyecto real solo con ARQHIA (ej. `todo-cli`) y
    exportarlo; que compile con `cargo run` fuera de ARQHIA.
6.  `git tag v1.0.0` + release notes; publicar `.deb` + Store.

## Riesgos
*   Nube real no lista → v1.0 se marca "Estable Local + nube mock"
    explícitamente; no se finge.
*   Paralelo sobre base sin sandbox: dos workers + mismo archivo → el
    fallback secuencial lo cubre, pero un `edit_file` con `old` ambiguo
    entre workers puede fallar → el auditor lo marca ISSUES y el fix lo
    reintenta en secuencial (los sandboxes con merge llegan en v1.1).
*   Empaquetado MSIX con escritura en `~/.config`/`~/.local/share`/workspace →
    probar rutas bajo el contenedor; usar `runFullTrust`.
*   Comercio propio en Store → validar política; si no, comercio Microsoft.
*   `latest.json` mal versionado → validar semver en el script de release.
