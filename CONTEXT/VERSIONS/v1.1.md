# v1.1 — Pro (Linux + Windows): sandboxes + merge + agentes/flujos + licencias

## Objetivo
Monetizar sin frenar el STACK. El STACK (local + nube) queda gratis e
ilimitado para maximizar el efecto red. Pro cobra solo potencia para
indies/freelance: workers paralelos aislados con merge tipo git,
multi-workspace, agentes personalizados y flujos visuales. Backend mínimo:
sin servidor propio; licencias offline firmadas + proveedor de pago externo
(Lemon Squeezy / Paddle / Gumroad).

> Los workers asíncronos base (2–3 en paralelo sobre `Project/`) ya viven en
> v1.0 §F. v1.1 los aísla en sandboxes, sube el tope a 8 y añade merge.

Depende de v1.0 estable (STACK nube + auth + updater + Store + web).
**macOS no entra aquí**: se movió a v1.2, condicionado a base de usuarios PRO.

## Principio de monetización (vinculante)
*   STACK gratis e ilimitado en Free y Pro: `push/pull/search_cloud`, nº de
    snippets y búsquedas nunca se gatean. Ver `POLICIES.md` §6.
*   Se cobra por: nº de workers paralelos, nº de sandboxes activos,
    agentes custom y flujos custom. Nada más en v1.1.
*   Sin telemetría de código para facturar. La licencia se valida offline.

## Alcance (concreto)

### A. Licencias y planes
*   Nuevo `src/license.rs`: `License { email, tier: Free|Trial|Pro, exp: i64 (unix), sig: String }`.
    Firma `ed25519` con clave pública embebida (crate `ed25519-dalek`).
    Guardado en `~/.config/arqhia/license.toml` con permisos `600`
    (igual que `cloud_token` v1.0). `is_pro() = firma válida && exp > now`.
*   Planes v1.1 (USD, solo hasta 6 meses; anual/lifetime definidos pero ocultos):
    `Trial 0 USD 30 días sin tarjeta (1 por email/dispositivo)` →
    `Mensual $5 (30d)` → `Trimestral $12 (90d)` → `Semestral $20 (180d)`.
    Anual `$40` y Lifetime `$129` existen en el enum pero la UI los marca
    "Próximamente" y el validador los rechaza hasta activarlos.
*   Renovación extiende `exp` actual (`exp = max(now, exp) + días`), no pisa.
    Gracia de 7 días tras expirar: pasa a Free sin bloquear proyectos.
*   `Config → Cuenta`: estado (`Free / Trial X días / Pro hasta fecha`),
    `text_input(pegar key) + button(Activar)`, `button(Pasar a Pro → URL pago)`,
    aviso Trial una sola vez. Free ve las funciones Pro con 🔒 y modal de upgrade.
*   Compra sin backend: web externa emite la key firmada por email; la app
    solo valida. Re-validación online opcional cada 30 días vía `fetch_url`
    contra la API del proveedor de pago (reusa allowlist `net_domains`).

### B. Multi-agent + multi-workspace con merge tipo git (Pro)
*   `workspace::snapshot_ws(base, task_idx) -> PathBuf`: copia a
    `{ws}/.arqhia/work/task-N/` con `walkdir`, ignorando `target/`, `.git/`,
    `node_modules/`, `.arqhia/work/`, `*.lock`, binarios y `uploads/` sobre tope.
    Reusa `canonicalize` + guard v0.9.4. Límite `Limits::max_sandbox_mb`.
*   `app/orchestrator.rs`: los `drivers: Vec` de v1.0 pasan de base a
    `ws = sandbox(task_idx)`; el sandbox no lee otros sandboxes ni escribe en
    base. Free mantiene el paralelo base v1.0 (1–3 workers); Pro desbloquea
    sandboxes + hasta 8.
*   `Limits`: `max_workers 1–8 (Free≤3 sin sandbox, Pro=8 con sandbox)`. Si el snapshot supera el tope,
    cae al paralelo base v1.0 (o a secuencial) con aviso en el Log.
*   Nuevo `agent/merge.rs`: `diff_sandbox(base, sandbox) -> Vec<FileOp>` por
    tamaño+mtime y hash. Merge file-level v1.1 (no hunk-level):
    archivos distintos entre workers → auto-copia a base con log
    `task-01: src/a.rs → base`; mismo archivo tocado por >1 worker →
    conflicto: no copia, genera `CONTEXT/MERGE.md` con bloques
    `base / task-01 / task-02`, llama al auditor para proponer fusión y pide
    aprobación con el modal `Aprobar/Denegar` v0.6. `cleanup_work()` borra
    `.arqhia/work/` tras merge OK (a papelera si hay conflicto).
*   Auditor final corre sobre la base ya mergeada (reusa `audit_workspace`).
*   Multi-workspace Pro = varios sandboxes + `extra_paths` por tarea.

### C. Agentes custom + flujos visuales en cadena (Pro)
*   Nuevo `src/custom.rs`: `AgentSpec { name, description, system_extra, tools: Vec<String>, model (vacío = active), max_iters }`,
    `FlowSpec { name, description, steps: Vec<StepSpec> }`,
    `StepSpec { id, kind: StepKind, prompt, tools }`,
    `StepKind { Leer | Contexto | Editar | Refactorizar | Ejecutar | Auditar }`.
    Cada kind trae `system_extra` + tools por defecto. Persistencia TOML en
    `~/.config/arqhia/agents/*.toml` y `flows/*.toml` (+ `list/load/save` con
    validación: nombres únicos, tools subset, 1–12 pasos por flujo).
*   Editor visual sin canvas (Iced 0.13 no tiene drag&drop barato):
    pestaña `Config → Agentes`: izquierda lista + `+ Nuevo`; centro cadena
    vertical de tarjetas `rounded_box` con `pick_list(Kind) + text_input(nombre)
    + text_input(prompt) + checkboxes tools + [↑][↓][x]`; `+ Añadir paso` abajo.
    Chat header: `pick_list(agente) + pick_list(flujo)`; Free los ve con 🔒.
*   Intérprete en `orchestrator.rs`: `run_flow(flow, task)` recorre pasos en orden;
    cada paso = `llm_step` con `system = worker_system + agent.system_extra +
    step.prompt` y policy filtrada por `step.tools` (tool no listada → denegada
    por rol, como el planner v0.7, con test). Log muestra fase actual
    `flujo: editar (2/3)`.

## Criterio Done (estricto)
*   Instalación limpia = Free, STACK funciona sin key; key inválida/expirada →
    rechazo claro sin romper Free.
*   Free intenta 2º worker / 2º sandbox / agente o flujo custom → modal Pro +
    link, nada se ejecuta.
*   Pro E2E (Groq o Local): "crea a.txt y b.txt" → 2 sandboxes → merge auto sin
    conflicto, base con ambos archivos, `.arqhia/work/` limpio.
*   Mismo archivo tocado por 2 workers → `MERGE.md` + propuesta auditor +
    aprobación.
*   Agente "Solo-lectura" pide `write` → denegado por rol; flujo
    `leer>editar>auditar` ejecuta 3 fases visibles en Log.
*   `cargo test` (licencia, merge conflicto, specs) + `cargo clippy --all-targets` verdes.

## Test de Funcionalidad
1.  Pegar key Trial → 30 días Pro, merge con 2 tareas disjuntas.
2.  Forzar conflicto (ambos editan `main.rs`) → `MERGE.md` + modal, papelera
    conserva sandboxes.
3.  Free: pick agente custom → 🔒 + URL pago; STACK sigue buscando sin key.
4.  Expirar key (fecha pasada) → gracia 7 días → Free, proyectos intactos.

## Riesgos
*   Snapshots grandes (`target/`, `node_modules`) → ignorados + `max_sandbox_mb`
    + caída a secuencial; nunca bloquear el turno.
*   `ed25519` mal integrado → keys falsificables; test de firma obligatorio +
    pubkey por env build.
*   Proveedor de pago cambia formato key → validador tolerante (trim,
    mayúsculas) + mensaje "revisa tu email".
*   Paralelo con 2 APIs distintas multiplica coste LLM del usuario → aviso en UI
    antes de lanzar (BYOK: el coste lo paga él).
